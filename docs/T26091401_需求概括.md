## 1. 项目定义
在 `D:\ABC\hello-dev\` 下新建一个零依赖的原生 HTML/CSS/JS 静态页，用于验证 DEV 工作流端到端跑通（建目录 → 写文件 → 语法校验）。

## 2. 核心功能范围

**做什么**
- 新建目录 `hello-dev/`，内含 4 个文件：`index.html`、`style.css`、`script.js`、`README.md`
- 页面初始渲染文本 `Hello DEV`
- 一个按钮；点击后该文本替换为 `DEV 工作流运行成功`
- `index.html` 以相对路径引用 `style.css` 与 `script.js`，双击即可 `file://` 打开
- `README.md` 写清目录结构 + 打开方式 + 交互说明
- 交付前执行 JS 语法检查（`node --check script.js`，无 Node 时降级为人工语法核对）

**不做什么**
- 不修改 `D:\ABC` 下任何现有文件
- 不引入 Vue / React / 构建工具 / CDN / npm 包 / 字体外链
- 不做后端、不做持久化（无 localStorage 等）、不做路由
- 不做响应式适配、浏览器兼容矩阵、视觉设计打磨、单测框架
- 不接入 CI

## 3. 技术栈约束
- 原生 HTML5 + 原生 CSS + 原生 JavaScript（ES2015+，不打包不转译）
- 事件绑定用 `addEventListener`（避免 inline `onclick`），DOM 用 `getElementById` / `textContent`
- 无网络请求、无外部资源；所有引用为同目录相对路径
- 目标运行环境：本地浏览器直接打开 `file://`

## 4. 关键验收标准（按优先级）
1. `hello-dev/` 下 4 个文件齐备，且项目其他文件零改动（`git status` 仅显示新增）
2. 双击 `index.html` 打开后页面可见 `Hello DEV`，控制台无报错、无 404 资源
3. 点击按钮后目标文本准确变更为 `DEV 工作流运行成功`（字符串完全一致，含"DEV"与"工作流运行成功"之间的单空格）
4. `script.js` 通过 `node --check`（或等效语法验证），退出码 0
5. `README.md` 说明文件结构、打开方式、交互预期

## 5. 风险清单
| # | 风险 | 影响 | 处置 |
|---|---|---|---|
| 1 | `validation_commands` 槽位缺失，环境是否装 Node 未确认 | 无法执行 `node --check`，验收项4落空 | 先探测 `node -v`；不可用则降级为语法人工核对并在交付说明中标注 |
| 2 | 目标路径为 Windows（`D:\ABC`），中文文本 + 文件编码易出 BOM/GBK | 页面显示乱码，验收项2/3失败 | 4 个文件统一 UTF-8 无 BOM；`index.html` 声明 `<meta charset="UTF-8">` |
| 3 | 文本精确匹配风险：按钮文案与结果文案可能混用同一元素 | 交互结果字符串不符，验收项3失败 | 分离"状态显示元素"与"按钮元素"，仅改前者 `textContent` |

无阻塞性未决项，可直接进入 Build。

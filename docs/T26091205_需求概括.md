# 需求概括 · hello-dev 静态演示页

## 1. 项目定义
在 `D:\ABC` 下新开一个零依赖的四文件静态页，跑通"渲染 + 一次点击状态切换"，用来验证 DEV 工作流本身能落地、能自证。

## 2. 核心功能范围

**做什么**
- 新建目录 `D:\ABC\hello-dev\`
- 四个文件：`index.html`、`style.css`、`script.js`、`README.md`
- 页面初始文案：`Hello DEV`
- 一个按钮，点击后目标文字变为 `DEV 工作流运行成功`（文案切换为一次性覆盖，不做回滚/状态机）
- `style.css`、`script.js` 由 `index.html` 以**相对路径**外链引入（这是"双击可打开"的前提，不内联也不走绝对路径）
- `README.md` 写清项目结构 + 运行方式
- 收尾做一轮基础验证（JS 语法检查等，命令由执行侧按本机可用工具自选）

**不做什么**
- 不引入 Vue / React / 任何前端框架、CDN、npm 包、构建产物
- 不发网络请求、不做 fetch/XHR、不接后端
- 不做响应式适配、不做视觉设计稿还原、不做浏览器兼容矩阵
- 不新增测试框架、不做 E2E
- **不改动 `D:\ABC` 下任何现有文件**（受保护区，见风险 R1）

## 3. 技术约束
- 原生 HTML + CSS + JavaScript，ES2015+ 语法即可，无需 polyfill
- `file://` 协议下必须可用：不出现任何需要 http 服务才成立的特性（ESM `type="module"` 在部分浏览器 `file://` 下会被 CORS 拦，建议用传统 `<script src>` 非模块写法）
- 脚本需保证 DOM 就绪后再绑定事件（`defer` 或 `DOMContentLoaded`，二选一）
- 编码 UTF-8，`index.html` 需显式 `<meta charset>`，否则中文按钮/文案在双击场景下易乱码
- 目标路径为 Windows（`D:\ABC`），相对路径引用不得写反斜杠

## 4. 关键验收标准（按优先级）
1. **零侵入**：`hello-dev/` 外无任何文件被新建、修改或删除。
2. **功能可跑**：双击 `index.html` 打开即显示 `Hello DEV`；点击按钮后该文字变为 `DEV 工作流运行成功`；控制台无报错。
3. **依赖纯净**：四个文件内不出现框架引用、外部 URL、`node_modules`、打包器配置。
4. **结构完整**：四文件齐备，CSS/JS 确实被外链加载（非空文件、非死链）。
5. **文档可读**：`README.md` 至少覆盖目录结构说明与"如何打开"两步。
6. **自证留痕**：产出一次可复核的验证结果（语法检查通过输出，或等效的静态校验结论）。

## 5. 风险清单
- **R1｜工作目录非空且缺元信息（阻塞项）**：`D:\ABC\AGENTS.md` 不存在，项目约定无法读取；工作区既有内容未知，"不修改现有文件"缺少对照基线。建议执行前对 `D:\ABC` 做一次文件清单快照，交付时比对。参见项目AGENTS.md（若后续补齐则以其为准）。
- **R2｜验证命令未指定**：`validation_commands` 为空。若本机无 Node，`node --check` 不可用。需按序降级：`node --check hello-dev/script.js` → 其他可用 JS 语法工具 → 至少完成文件存在性/外链路径一致性的静态核对，并在交付里写明实际用了哪条，不要以"无工具"跳过。
- **R3｜"双击打开"的隐性破点**：中文乱码与 ESM/`file://` 拦截是两类最容易翻车的点，且都不报错在半途、而是白屏或乱码。交付前须真人双击验一次，不能只做语法检查就判通过。

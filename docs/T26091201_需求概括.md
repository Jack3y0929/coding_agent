## 1. 任务概述

### 1.1 任务目标

## 需求概括 · hello-dev 静态页

### 1. 项目定义
在 D:\tanchi 下新增一个隔离的 `hello-dev` 目录，交付一个双击即开的原生 HTML/CSS/JS「Hello DEV」演示页，零依赖、零侵入。

### 2. 核心功能范围

**做什么**
- 新建 `hello-dev/` 目录及四个文件：`index.html`、`style.css`、`script.js`、`README.md`
- 页面初始渲染文字「Hello DEV」
- 提供一个按钮，点击后把该文字替换为「DEV 工作流运行成功」
- 文本、样式、行为三分离：DOM 在 html，样式在 css，逻辑在 js
- `README.md` 写清项目结构 + 运行方式（双击 `index.html`）
- 交付后跑一次 JS 语法检查（`node --check`）或等效基础验证

**不做什么**
- 不改动 `hello-dev/` 以外的任何现有文件
- 不引入 Vue / React / 任何前端框架、构建工具、npm 包、CDN 资源
- 不做后端、不做持久化、不做路由、不做单测框架接入
- 不做响应式适配、动效、多语言、主题切换等超出验收的修饰
- 不新增配置文件（package.json / tsconfig 等），保持纯静态可直开

### 3. 技术约束
- 原生 HTML5 + CSS3 + ES 纯 JavaScript，无编译步骤
- `index.html` 必须能通过 `file://` 双击直接运行 → 禁用 ES Module（`type="module"` 在 file 协议下会被 CORS 拦）、禁用 fetch 本地资源、用相对路径引用 css/js
- 目录隔离：所有产物落在 `hello-dev/` 下
- 环境：Windows，目标项目根 `D:\tanchi`
- 已核实事实：`hello-dev` 在项目中不存在（无命名冲突）；项目根 `AGENTS.md` **当前不存在**——参见项目AGENTS.md（若后续补建，按其约定执行）
- 不要调用cat07-debug技能

### 4. 关键验收标准（按优先级）
1. **零侵入**：`hello-dev/` 外无任何文件被新建/修改/删除（实现前后各做一次差异确认）
2. **可直开**：双击 `index.html` 在浏览器正常渲染，控制台无报错、无 404 资源
3. **功能生效**：初始文案 = 「Hello DEV」；按钮存在且可点击；点击后目标文案 = 「DEV 工作流运行成功」（严格字符一致，含大小写与空格）
4. **技术合规**：源码中无框架引用、无外部 URL 依赖，仅三个静态文件互引
5. **文档可读**：`README.md` 说明目录结构 + 运行方式
6. **验证留痕**：执行 JS 语法检查并给出结果（通过/失败输出）

### 5. 风险清单

| # | 风险 | 影响 | 处置 |
|---|---|---|---|
| R1 | 环境无 Node，`node --check` 不可用 | 验收项 6 无法自动化 | 降级为静态自查（引号配对、括号闭合、`getElementById` 与 DOM id 一致性）并在 README/交付说明中写明验证方式受限 |
| R2 | 误触碰现有文件（如顺手改根目录 index、格式化全局配置） | 违反最高优先级验收项 1 | 全程只在 `hello-dev/` 下写入；交付前比对目录清单 |
| R3 | file:// 协议下误用 module / fetch 导致按钮脚本不加载 | 验收项 2、3 直接失败 | 强制用普通 `<script src="script.js">` + `DOMContentLoaded`，绑定前确认元素存在 |

——
复杂度：低。纯新增、无既有逻辑耦合、无数据迁移。可直接进 Build。

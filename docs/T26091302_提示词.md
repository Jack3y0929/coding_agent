## 二、各文件实现设计

### 1. `hello-dev/index.html`
- `<!DOCTYPE html>` + `<html lang="zh-CN">` + `<meta charset="UTF-8">`（**关键**：页面含中文文案 `DEV 工作流运行成功`，缺失 charset 在 `file://` 下会乱码）+ `<meta name="viewport">`
- `<head>` 内 `<link rel="stylesheet" href="./style.css">`（**相对路径 + `./` 前缀**，保证双击 `file://` 直开可用）
- `<body>` 结构：
  - `<main class="card">` 容器
  - `<h1 id="message" class="title">Hello DEV</h1>` ← 初始文案，**服务端（此处即静态 HTML）直出**，不依赖 JS 渲染
  - `<button id="runBtn" type="button" class="btn">运行 DEV 工作流</button>`
  - `<p id="status" class="status" role="status" aria-live="polite"></p>` ← 辅助状态行
- `<script src="./script.js" defer></script>` 置于 `</body>` 前（双保险：`defer` + body 末尾）
- **硬约束落地**：无 `type="module"`、无 `fetch`/XHR、无 `<link>` 指向任何 `http(s)://`、无 CDN 字体/图标、无 `<style>`/`<script>` 内联块、无 `onclick=` 内联事件属性、无 `style=` 内联属性

> 设计要点：`Hello DEV` 必须写在 HTML 里而非由 JS 注入。理由：若 JS 因任何原因未加载，验收项 1/2 仍成立，不会白屏；点击后的文案替换才是 JS 职责。

### 2. `hello-dev/style.css`
- 系统字体栈：`-apple-system, "Segoe UI", "Microsoft YaHei", sans-serif`（**不引任何外部字体文件**）
- `body` flex 居中 + 最小高度 `100vh`；`.card` 卡片留白、圆角、阴影
- `.title` 字号层级；`.btn` 常态 / `:hover` / `:active` / `:focus-visible`（键盘可访问）/ `:disabled`（点击后置灰）
- `.status` 次要文案色；`.status--ok` 成功态色
- 移动端不做专门断点（需求明确排除响应式适配），仅靠 flex 自然换行

### 3. `hello-dev/script.js`
- 顶层 `'use strict';` + IIFE 包裹，避免污染全局
- **无函数抽象需求，采用单函数 + 单入口**（保持最小可读）：
  - `const TEXT_INITIAL = 'Hello DEV'`、`const TEXT_SUCCESS = 'DEV 工作流运行成功'` 常量置顶，文案集中管理
  - `function renderSuccess(messageEl, statusEl)`：替换 `textContent`、追加 `card--done` 类、更新 `status.textContent`、`btn.disabled = true`（幂等保护，避免重复点击产生歧义状态）
  - `function init()`：`document.getElementById` 取 `message` / `runBtn` / `status` → **空值守卫** → `addEventListener('click', ...)`
- 全部 DOM 读写用 `textContent`，不用 `innerHTML`
- 因 `defer` 保证 DOM 就绪，**不使用** `DOMContentLoaded`（多一层无用嵌套）；但守卫逻辑已能兜住极端时序

**数据流（单向、无状态容器）**
```
HTML 直出 "Hello DEV"
      │
用户 click #runBtn
      ▼
事件监听器 ──► 校验元素存在 ──► #message.textContent = "DEV 工作流运行成功"
                              ├─► #status.textContent = 提示
                              ├─► .card 追加 done 类 ──► CSS 过渡生效
                              └─► #runBtn.disabled = true（终态，无回退路径）
```
无模块、无路由、无持久化、无网络请求、无异步。

**异常处理策略**（目标是「控制台零报错」验收项 1）
| 场景 | 处置 |
|---|---|
| 三个 id 中任一元素缺失 | `console.error('[hello-dev] 缺少必要元素: xxx')` 后 `return`，**不 throw**（未捕获异常会产生红色报错，直接挂验收项 1） |
| `document` 未就绪 | 由 `defer` 消除；元素取不到时走上一条守卫 |
| 重复点击 | 按钮 `disabled` 拦截；即便程序化再次触发，赋同一 `textContent` 天然幂等 |
| 浏览器禁用 JS | 页面仍完整显示 `Hello DEV`（降级为静态页，不白屏） |
| 中文乱码 | `<meta charset="UTF-8">` + 文件以 UTF-8 无 BOM 写入 |

### 4. `hello-dev/README.md`
固定小节：`简介`（一句话：Just_codding 工作流端到端静态探针）、`目录结构`（4 文件树 + 各自职责）、`运行方式`（双击 `hello-dev/index.html`，或浏览器地址栏 `file:///D:/ABC/hello-dev/index.html`；**明确说明无需服务器、无需安装依赖、无需构建**）、`交互说明`（初始 `Hello DEV` → 点击按钮 → `DEV 工作流运行成功`）、`技术说明`（原生 HTML/CSS/JS，无 Vue/React/CDN；并说明为何不用 `type="module"`——`file://` 下会被 CORS 拦截）、`验证结果`（**Build 阶段填入实际执行的命令与真实输出，不伪造**）。

## 五、实现说明（供审查者参考的关键决策）

- **文案静态直出 + JS 只做替换**：把「渲染」和「交互」解耦，任何 JS 失效都不会导致白屏，最大化验收项 1/2 的稳健性。
- **`defer` 而非事件监听**：在 `file://` 场景下 `defer` 是最可靠的 DOM 就绪手段，且不引入 `DOMContentLoaded` 嵌套；同时严格避开 `type="module"`（`file://` 协议下 ES Module 受同源策略限制会静默失败）。
- **常量置顶 + `textContent`**：文案是唯一「配置」，集中便于审查比对验收标准；禁用 `innerHTML` 既避免 XSS 面也避免解析开销。
- **点击后 `disabled`**：把「一次性工作流」的语义显式编码进 UI，防止重复点击造成的状态歧义（需求未要求，但属低成本正确性提升，不扩大范围）。
- **不抽公共工具函数、不加事件委托**：单页面单按钮，抽象是负资产——遵循「不炫技」原则。
- **零改动保证**：所有写入路径均在 `hello-dev/` 前缀下，写入前 `dir` 预检、写入后 `dir` + `git status` 双重复核。

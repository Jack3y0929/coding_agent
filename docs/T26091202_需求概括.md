## 1. 任务概述

### 1.1 任务目标

## 需求概括：hello-dev 静态演示页

### 1. 项目定义
在项目根 `D:\ABC` 下新建独立文件夹 `hello-dev`，做一个零依赖的原生三件套页面，跑通"Hello DEV → 点击按钮 → DEV 工作流运行成功"这条最小交互链路。

### 2. 核心功能范围

**做什么**
- 新建 `hello-dev/` 目录及 4 个文件：`index.html`、`style.css`、`script.js`、`README.md`
- 页面初始文案显示 `Hello DEV`
- 页面放 1 个按钮，点击后目标文案替换为 `DEV 工作流运行成功`
- `style.css` 做基础排版/按钮样式（够看清即可，不做视觉设计）
- `README.md` 写清：目录结构 + 怎么跑（双击 index.html）+ 交互说明
- 交付后执行 JS 语法检查等基础验证

**不做什么**
- 不引入 Vue / React / 任何 CDN、npm 包、构建工具
- 不改、不删、不动 `D:\ABC` 下任何现有文件
- 不在 `hello-dev/` 之外新增文件（含根级 `AGENTS.md`）
- 不做后端、接口、路由、状态持久化、单测框架
- 不做响应式适配与浏览器兼容矩阵（按现代浏览器即可）

### 3. 技术约束
- 纯原生 HTML + CSS + JavaScript
- `index.html` 双击即开 → 资源引用必须**相对路径**（`style.css` / `script.js`），走 `file://` 协议
- `<script>` 标签**不得使用 `type="module"`**，`file://` 下 ES Module 会被 CORS 拦截，直接白屏
- 文案替换用 DOM 文本节点操作（`getElementById` + `textContent`），不用 `innerHTML`
- 无验证命令清单（`validation_commands` 为空），验证手段需现场自定

### 4. 关键验收标准（按优先级）
1. `hello-dev/` 及 4 个文件全部存在，根目录其他文件零改动（改前/改后 diff 为空）
2. 双击 `index.html` 能直接打开，控制台无 404、无报错
3. 初始渲染可见 `Hello DEV`
4. 点击按钮后文案变为 `DEV 工作流运行成功`，且幂等（多点不乱加节点）
5. `node --check script.js` 通过（或等价语法校验），README 能让人照做跑起来

### 5. 风险清单
1. **验证工具链未知**：环境是否装有 Node 未确认。若 `node --check` 不可用，需提前定降级方案（人工静态审查 / 浏览器 Console 报错截图作为验证凭据），否则第 5 条验收卡住。
2. **file:// 协议限制**：一旦误用 `type="module"`、绝对路径或 `fetch` 本地 JSON，双击打开即失效——"双击可打开"是本任务最易踩翻的硬指标。
3. **根目录缺 `AGENTS.md`**：已核实 `D:\ABC\AGENTS.md` 不存在，根目录也无可搜索源码。参见项目 AGENTS.md 的规范无法落地；但受 change_scope 限制不新建根级文件，只在 README 内注明。不要调用 cat07-debug 技能。

## 1. 任务概述

### 1.1 任务目标

## 需求概括：计算器功能

### 1. 项目定义
在 D:\ABC 内新增一个计算器功能，输入数值与运算符，返回运算结果。

### 2. 核心功能范围

**做什么（MVP 最小闭环）**
- 两个操作数 + 四则运算（+ − × ÷），输出结果
- 除数为 0 不崩，给出可识别的异常结果
- 非数值输入不崩，给出可识别的提示
- 结果以十进制数值呈现，浮点误差不扩大

**不做什么（本次不碰）**
- 表达式解析、括号、多目连续运算、优先级求值
- 科学函数（幂、三角、对数）、历史记录、单位换算
- 主题美化、响应式适配、国际化、埋点
- 不动项目既有功能：已核实 D:\ABC 全库无 `calc|计算` 相关代码，本功能是纯新增，无既有实现可复用，也不得反向改造既有文件

> 已核实事实：项目内至少存在一处原生 JS 代码，形态为 IIFE + `"use strict"` + `getElementById` + `DOMContentLoaded` 的 DOM 绑定风格。新代码默认与之保持一致。

### 3. 技术约束

| 项 | 状态 | 默认取值 |
|---|---|---|
| 技术栈 | 未指定 | 沿用已观察到的原生 JS，不引第三方库 |
| 框架 / 构建链 | 未核实 | 不新增依赖、不加构建步骤 |
| 落点文件 | 未指定 | 新增独立文件，不并入既有文件 |
| 运算逻辑与 DOM 的关系 | 未指定 | 拆两层：纯函数核心 + 薄壳事件绑定 |

第 4 项是硬要求：纯函数层不触碰 DOM，否则无法脱离页面验证。

### 4. 关键验收标准（按优先级）

1. 四则运算结果正确，含小数与负数用例（`0.1+0.2`、`7/2`、`-3*4`）
2. 除零、非数值输入返回可判定结果，不抛未捕获异常
3. 现有测试全绿，且无既有测试被删除或改断言来迁就新代码
4. 人工验收：在 D:\ABC 现有页面入口能实际触发并看到结果
5. 不改动既有文件行为

### 5. 风险清单

1. **"现有测试通过"无法自动判定** —— 已确认槽位里 `validation_commands` 为空，测试运行命令未落地，验收第 3 条会卡在这里，需先补齐一条可执行命令。
2. **落点未定，change_scope 为空** —— 计算器挂到哪个页面、用什么文件名，直接影响是否触碰既有 DOM 结构；`target_modules` 只写了"项目内相关文件"，等于没约束。
3. **交付形态二义** —— "计算器"可读作纯函数模块，也可读作可点页面。选错方向会导致人工验收（第 4 条）不通过而返工。当前按"纯函数 + 页面入口"两层同时交付规避，若只需其中一层，需在开发前砍掉。

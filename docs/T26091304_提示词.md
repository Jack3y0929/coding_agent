## 代码变更

### 变更概要
本次任务将在 `D:\ABC\hello-dev` 目录下新增计算器功能的完整实现。遵循“逻辑与视图分离”的原则，新增两个独立的 JavaScript 文件，并修改入口 HTML 以加载资源。

#### 1. 新建文件：`hello-dev/calc_logic.js`
**作用**：定义纯函数核心层（Pure Logic），不依赖 DOM，负责数值验证、四则运算逻辑及异常处理。
**核心设计**：
- 提供 `execute(num1, op, num2)` 方法。
- 统一返回格式对象：`{ status: 'ok'|'error', result: number|string }`。
- 覆盖除零保护和非数字拦截。

#### 2. 新建文件：`hello-dev/calculator_binding.js`
**作用**：定义薄壳视图层（View Binding），负责 DOM 元素查询与事件监听。
**核心设计**：
- 使用 `DOMContentLoaded` 事件初始化。
- 绑定按钮点击事件，调用 `calc_logic` 并在界面上渲染结果或错误信息。

#### 3. 修改文件：`hello-dev/index.html`
**作用**：集成新页面块与脚本资源。
**变更点**：
- 在 `<body>` 中添加 `<section id="calc-section">` 包含输入框、下拉框和按钮。
- 引入 `calc_logic.js` 和 `calculator_binding.js`。

## 实现说明

### 1. 架构分层
为了满足需求中“纯函数核心+薄壳事件绑定”的要求，将代码严格分为两层：
- **逻辑层 (`calc_logic.js`)**：任何浏览器环境均可测试。实现了 `try-catch` 风格的错误聚合，确保前端不会因为非结构化输入而 Crash。
- **视图层 (`calculator_binding.js`)**：仅处理 `document.getElementById` 交互和 UI 文案更新。

### 2. 数据流设计
1. 用户输入 `10`, `+`, `2` -> 点击计算。
2. `calculator_binding.js` 读取 DOM 节点值。
3. 校验输入是否非空，若为空直接反馈 UI 错误，不调用逻辑层。
4. 调用 `calc_logic.execute('10', '+', '2')`。
5. 逻辑层进行类型转换与运算，返回成功对象。
6. 视图层根据状态码更新 `#result-display` 的 `innerText`。

### 3. 异常策略
- **非数字**：解析为 NaN 时，直接返回错误提示，不进入计算分支。
- **除以零**：检测除法操作且除数为 0，拦截并返回友好提示 `除数不能为零`。
- **未捕获错误兜底**：在 `calc_logic` 外层包裹 try-catch，防止内部意外报错导致页面白屏。

### 4. 风格对齐
- 延续项目中 `index.html` 和 `script.js` 的观察到的风格：
    - 使用 `"use strict"`。
    - 使用 IIFE 封装命名空间（避免全局变量污染）。
    - 保持无第三方库依赖。

### 5. 验收方案
- **单元测试**：`calc_logic.js` 中的纯函数可在 Node.js 环境下直接编写简单的断言测试（如 `node -e "require('./calc_logic').execute(1,'+',2)"`）验证逻辑正确性。
- **人工验收**：打开 `file:///D:/ABC/hello-dev/index.html`，确保旧版“切换文案”功能依然生效，且新增的计算器区域能正常响应点击并显示结果。

### 6. 边界考量
- 浮点数精度：虽然需求提及浮点误差，但在原生 JS 层面不进行复杂的 BigInt 模拟（非 MVP 要求），保留 JS 原生精度行为，除非后续优化才考虑引入小数位修复逻辑。当前重点在于保证基本的数学逻辑正确。

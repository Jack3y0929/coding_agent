## 1. 任务概述

# 需求概括 · hello-dev 静态页面

**任务类型**：DEV（新增，零改动）｜**风险等级**：low｜**置信度**：0.98

## 1. 项目定义
在当前项目根目录（`D:\ABC`）下新增 `hello-dev` 文件夹，用原生 HTML/CSS/JS 交付一个可双击打开的 Hello DEV 演示页，含按钮点击文案切换，并附带 README 说明。

## 2. 核心功能范围

**做什么（Do）**
- 新建目录 `hello-dev/`，内含且仅含 4 个文件：`index.html`、`style.css`、`script.js`、`README.md`
- 页面可见标题文案 `Hello DEV`
- 页面含 1 个按钮；点击后目标文案变为 `DEV 工作流运行成功`
- CSS/JS 以独立文件形式被 `index.html` 引用（相对路径，便于 file:// 直开）
- README 写明：目录结构、各文件职责、运行方式（双击 `index.html`）、验证方式
- 交付前执行基础验证（见 §4 第 5 条）

**不做什么（Don't）**
- 不修改、不删除、不重命名 `D:\ABC` 下任何现有文件
- 不引入 Vue / React / 构建工具 / CDN / npm 包 / 任何外部依赖
- 不做后端、持久化、网络请求、路由、多页面
- 不做浏览器兼容矩阵、响应式断点、视觉设计系统的额外要求
- 文案切换不要求可逆（点击后回滚为 `Hello DEV` 未指定）

## 3. 技术约束
- 原生 HTML5 + 原生 CSS + 原生 JavaScript（ES 语法，无转译）
- 零外部依赖：无 `<script src>` 外链、无字体/CDN 引用
- 直接在 `file://` 协议下可运行（不依赖本地 HTTP 服务、不涉及 module 跨域限制）
- 变更范围白名单：`hello-dev/`；保护路径：项目其余全部现有文件

## 4. 关键验收标准（按优先级）
1. `hello-dev/` 目录存在，且 `index.html`、`style.css`、`script.js`、`README.md` 四文件齐备
2. 双击 `index.html` 可正常渲染：显示 `Hello DEV`，存在一个可点击按钮
3. 点击按钮后，文案变为 `DEV 工作流运行成功`（无控制台报错）
4. 仅原生三件套实现，代码中无框架、无外部依赖引用；项目现有文件零改动
5. 交付时附带一次基础验证结果：`script.js` 语法检查通过（如 `node --check hello-dev/script.js`，或本机可用的等价静态检查），无 Node 环境时降级为文件存在性 + 关键字符串（`Hello DEV`、`DEV 工作流运行成功`）自检并如实说明所用手段
6. `README.md` 含目录结构 + 运行方式说明

## 5. 风险清单
1. **验证命令缺位（missing_slots: validation_commands）**：目标机 `node` 是否可用未核实；需在实现阶段先探测，探测失败必须降级并明示，不得跳过验证环节。
2. **file:// 隐式限制**：若使用 `type="module"` 或绝对路径引用，双击打开会因跨域/路径解析失败——坚持普通 `<script src="script.js">` 相对引用。
3. **“不修改现有文件”的可验证性**：当前根目录两次全量检索均无命中，工作区看似为空；该约束实际为“仅新增、不触碰其他路径”，交付需以文件清单自证（变更仅限 `hello-dev/`）。

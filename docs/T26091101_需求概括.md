# 需求概括 · hello-dev 静态演示页

**一句话定义**：在 D:\tanchi 根下新建独立的 `hello-dev/` 目录，用纯原生三件套交付一个可双击打开的 Hello DEV 演示页，零侵入现有工程。

## 1. 项目定义
调研/工作流验证用的最小静态页面。目的不是产物本身，而是验证"建目录 → 写文件 → 双击可跑 → 语法自检"这条链路是否走通。

已核实：当前项目内不存在 `hello-dev` 相关代码，无命名冲突，属全新独立目录。

## 2. 核心功能范围

**做什么**
- 新建 `hello-dev/`，内含 4 个文件：`index.html`、`style.css`、`script.js`、`README.md`
- 页面渲染标题文案 "Hello DEV"
- 页面上放一个按钮；点击后该文案原地替换为 "DEV 工作流运行成功"（单次点击生效，不要求可逆）
- `style.css` 由 `<link>` 引入，`script.js` 由 `<script src>` 引入，均为相对路径
- README 写清：目录结构、打开方式（双击 index.html）、功能说明

**不做什么**
- 不做构建工具、包管理、`node_modules`、`package.json`
- 不做框架（Vue/React/Svelte 等）、不做 CDN 外链、不做字体/图标等任何外部资源
- 不做后端、接口请求、`fetch`、localStorage
- 不改当前项目任何现有文件（含 AGENTS.md、配置文件、既有目录）
- 不做路由、多页、响应式适配、无障碍、单测

## 3. 技术约束
- 原生 HTML + CSS + JavaScript，ES 语法保持浏览器直跑级别
- **禁止 `type="module"`** —— `file://` 协议下 ES Module 会被 CORS 拦截，直接破坏"双击可打开"
- **禁止顶层 `await`、禁止 import/export** —— 同上原因
- 脚本需防执行时序问题：`<script>` 放 `</body>` 前，或等 DOM ready
- 文案节点需有稳定 id/class，JS 用 `getElementById` 取，不做魔法选择器
- 目录写入范围严格锁定 `hello-dev/`，视为受保护路径清单之外的唯一可写区

## 4. 关键验收标准（按优先级）
1. **零侵入**：`git status`（或等价比对）显示改动仅落在新增的 `hello-dev/` 内，现有文件哈希无变化
2. **文件齐备**：`hello-dev/` 下四个文件全部存在且非空
3. **双击可用**：不启任何本地服务，直接双击 `index.html`，浏览器渲染出 "Hello DEV" 且控制台零报错
4. **交互达标**：点击按钮后，文案变为 "DEV 工作流运行成功"
5. **自检通过**：交付前跑 `node --check hello-dev/script.js`；无 node 时降级为人工静态审查（括号闭合、引号配对、DOM id 一致性），并在交付说明里注明实际采用的验证方式

## 5. 风险清单

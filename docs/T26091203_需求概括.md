## 1. 项目定义
在当前项目根目录新建 `hello-dev/`，交付一个零依赖、双击即开的原生 HTML/CSS/JS 演示页：显示 "Hello DEV"，点按钮切换文案为 "DEV 工作流运行成功"。

## 2. 核心功能范围

**做：**
- 新建目录 `hello-dev/`（路径：`D:\ABC\hello-dev\`）
- 四个新文件：`index.html`、`style.css`、`script.js`、`README.md`
- 页面初始文案 "Hello DEV"
- 一个按钮，点击后该文案变为 "DEV 工作流运行成功"（单次点击生效、结果可重复触发）
- `style.css` / `script.js` 以相对路径被 `index.html` 引用
- `README.md` 写清项目结构 + 运行方式（双击 index.html）
- 落地后跑 JS 语法检查或等价基础验证

**不做：**
- 不引入 Vue / React / 任何框架、CDN、npm 包、构建工具
- 不改动当前项目任何现有文件（含配置、锁文件、README、CI）
- 不做后端、接口、持久化、路由、测试框架、动效
- 不改文案：两处字符串按原样硬校验

## 3. 技术栈约束
- 原生 HTML + 原生 CSS + 原生 JavaScript（无转译、无模块打包）
- `index.html` 必须 file:// 协议下可直接双击打开 —— 推论：禁用 ES Module（`type="module"` 在 file:// 下会被 CORS 拦），禁用绝对路径 `/xxx.css`，只用相对引用
- 无外部字体、无网络请求、无跨域资源

## 4. 关键成功标准（按优先级）

| P | 标准 | 验证方式 |
|---|---|---|
| P0 | 只新增、不修改：现有文件字节级不变 | 目录树 diff / 时间戳比对 |
| P0 | 四个文件齐全且在 `hello-dev/` 下 | `ls hello-dev` |
| P0 | 双击 `index.html` 打开，样式与脚本均加载成功，控制台零报错 | 浏览器人工 + 控制台 |
| P1 | 点击按钮后文字精确变成 "DEV 工作流运行成功"（无引号、无多余空格） | DOM 断言 |
| P1 | `script.js` 通过语法检查；README 覆盖"结构 + 运行方式"两节 | `node --check`（无 Node 则用编辑器/静态扫描兜底） |

## 5. 风险清单

1. **file:// 加载失败**：若用了 `type="module"` 或绝对路径，双击打开时脚本/样式静默失效 —— 直接击穿 P0"双击可开"。
2. **验证环节缺运行时**：环境若无 Node，`node --check` 不可用。需在 README 或交付说明里注明实际采用的兜底验证手段，不能留"已验证"空口结论。
3. **误触现有项目文件**：当前工作目录若存在同名 `hello-dev` 或根级 README，写入时应做存在性判断。已核实目前不存在，风险为低但需在实现时保持路径写死在 `hello-dev/` 内。

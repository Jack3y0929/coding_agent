## 2. 数据流设计

```text
index.html
  │
  ├── 引入 style.css（同目录相对路径）
  └── 引入 script.js（defer，同目录相对路径）

页面加载：
  1. 浏览器解析 index.html
  2. 加载 style.css
  3. script.js 在 DOM 解析完成后执行
  4. script.js 获取：
     - #status-text
     - #run-button
  5. 给 #run-button 绑定 click 事件
  6. 用户点击按钮
  7. 将 #status-text.textContent 设置为精确字符串：
     "DEV 工作流运行成功"
```

关键设计：状态显示元素与按钮元素分离，避免按钮文案污染目标结果文本。

### 3.3 新建 `hello-dev/script.js`

```js
const INITIAL_TEXT = "Hello DEV";
const SUCCESS_TEXT = "DEV 工作流运行成功";

function init() {
  const statusText = document.getElementById("status-text");
  const runButton = document.getElementById("run-button");

  if (!statusText || !runButton) {
    console.error("hello-dev 初始化失败：缺少 #status-text 或 #run-button。");
    return;
  }

  statusText.textContent = INITIAL_TEXT;

  runButton.addEventListener("click", function () {
    statusText.textContent = SUCCESS_TEXT;
    statusText.classList.add("success");
  });
}

if (document.readyState === "loading") {
  document.addEventListener("DOMContentLoaded", init);
} else {
  init();
}
```

## 5. 异常处理策略

### 5.1 DOM 元素缺失

`script.js` 对 `#status-text` 和 `#run-button` 做空值检查：

```js
if (!statusText || !runButton) {
  console.error("hello-dev 初始化失败：缺少 #status-text 或 #run-button。");
  return;
}
```

避免元素缺失时抛出未处理异常。

---

### 5.2 脚本执行时机

虽然 `script.js` 已带 `defer`，仍保留 `DOMContentLoaded` 兼容逻辑：

```js
if (document.readyState === "loading") {
  document.addEventListener("DOMContentLoaded", init);
} else {
  init();
}
```

降低因脚本提前执行导致找不到 DOM 的风险。

---

### 5.3 资源路径错误

只使用同目录相对路径引用：

```text
style.css
script.js
```

避免绝对路径、`./` 误写、文件名大小写或目录层级错误。

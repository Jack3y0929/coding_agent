## 1. 任务概述

### 1.1 任务目标

## 需求概括：hello-dev 静态演示页

**上下文核实**：`D:\ABC` 全库搜索无 `hello` 相关代码；`D:\ABC\README.md` 与 `D:\ABC\hello-dev\index.html` 均不存在。结论——**纯新增，零改动**，不存在覆盖既有实现的风险。

### 1. 项目定义
在 `D:\ABC` 下新建独立目录 `hello-dev`，交付一个可双击打开的原生静态页，验证「Just_codding 工作流端到端跑通」——不是业务功能，是流水线探针。

### 2. 核心功能范围

**做什么**
- 新建 `hello-dev/`，内含 4 个文件：`index.html`、`style.css`、`script.js`、`README.md`
- 页面初始渲染文案 `Hello DEV`
- 一个按钮，点击后该文案替换为 `DEV 工作流运行成功`
- `style.css` / `script.js` 外置引用，不写内联样式和内联脚本
- `README.md` 说明目录结构 + 运行方式（双击 `index.html`）

**不做什么**
- 不改动 `D:\ABC` 下任何现有文件（硬约束）
- 不引构建工具、包管理、`package.json`
- 不做路由、状态管理、后端、接口请求、持久化
- 不做响应式适配、多浏览器兼容测试、视觉规范对齐
- 不加按钮以外的交互元素

### 3. 技术约束
- 原生 HTML5 + 原生 CSS + 原生 JavaScript（ES 语法，浏览器直跑）
- 禁 Vue、禁 React、禁任何 CDN / 外部依赖（含字体、图标库）
- 必须走 `file://` 协议：脚本置于 `</body>` 前或用 `defer`；**不得使用 `type="module"` 与 `fetch`**，会被本地跨域策略拦截

### 4. 关键验收标准（按优先级）
1. `hello-dev/index.html` 双击即在浏览器正常渲染，无控制台报错
2. 初始可见文案 `Hello DEV`
3. 按钮可点击，点击后文案变为 `DEV 工作流运行成功`
4. 代码库中检索不到 Vue / React / 任何外部资源引用
5. `README.md` 覆盖项目结构与运行方式
6. `script.js` 通过语法检查（`node --check`，或同等可用手段）
7. `git status` 变更集只含 `hello-dev/`，其余文件 0 diff

### 5. 风险清单

| # | 风险 | 影响 | 处置 |
|---|---|---|---|
| 1 | `validation_commands` 槽位缺失，本机是否有 Node 未核实 | 阻塞验收项 6 | 先探测 `node -v`；无 Node 则降级为浏览器控制台 + `python -m` 静态检查，并在交付说明中标注实际采用的验证手段 |
| 2 | `file://` 下 ES Module / `fetch` 静默失效 | 页面白屏，验收项 1 直接挂 | 强制普通 `<script>`，DOM 就绪后再绑事件 |
| 3 | 目标机 Windows，路径大小写与同名目录易踩坑 | 可能误写到他处 | 写入前 `ls D:\ABC` 确认无同名残留，落地后再 `ls hello-dev` 复核 |

> 综合风险等级：low。唯一悬空项是验证命令，属可当场补齐的非阻塞缺口。
>
> 参见项目AGENTS.md。不要调用cat07-debug技能。

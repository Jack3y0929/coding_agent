# 需求概括：Hello DEV 静态页面

## 1. 项目定义
在空项目 D:\ABC 下新建 `hello-dev/`，产出一个零依赖、可双击直接打开的原生 HTML/CSS/JS 交互页，并附带自述文档与一次语法级验证。

## 2. 核心功能范围

**做什么**
- 新建目录 `D:\ABC\hello-dev\`，仅 4 个文件：
  - `index.html` — 承载标题文案「Hello DEV」+ 一个按钮，通过 `<link>` / `<script>` 相对路径引用同目录资源
  - `style.css` — 基础排版与按钮态样式
  - `script.js` — 绑定按钮 click，将文案元素文本替换为「DEV 工作流运行成功」
  - `README.md` — 说明目录结构、打开方式（双击 index.html）、交互说明
- 完成后对 `script.js` 执行可用基础验证（`node --check hello-dev/script.js`；无 Node 时降级为 JS 语法自查 / 打开控制台确认无报错）

**不做什么**
- 不引入 Vue / React / 构建工具 / CDN / npm 依赖
- 不新增图片、字体等二进制资源
- 不修改 `hello-dev/` 之外的任何路径（项目现有文件全部 protected）
- 不做后端、持久化、路由、多语言、响应式断点适配、可访问性专项
- 不改动全局 Git 配置、不清理或重排根目录

## 3. 技术栈约束
| 项 | 约束 |
|---|---|
| 语言 | 原生 HTML5 + CSS + JavaScript（ES 语法需兼容本地浏览器直开） |
| 依赖 | 零外部依赖，无 `node_modules`、无 `<script src="http…">` |
| 加载方式 | 相对路径引用，禁止依赖服务器；`file://` 协议下不得触发 CORS/模块报错（**不使用 `type="module"`，不使用 fetch**） |
| 写入边界 | 仅 `hello-dev/` 目录新建；根目录既有文件只读 |
| 变更范围 | `hello-dev/`（risk_level: low） |

## 4. 关键验收标准（按优先级）
1. **文案与交互闭环**：页面初始显示「Hello DEV」；点击按钮后该文字变为「DEV 工作流运行成功」；浏览器控制台无 error。
2. **零依赖直开**：双击 `index.html` 即在浏览器完成上述交互，样式生效（证明 style.css 被正确加载），无需任何本地服务器。
3. **隔离性**：`hello-dev/` 外文件字节级无变动，无临时/多余文件残留。
4. **文档自洽**：README.md 含目录结构表 + 运行方式 + 交互预期，能让人不读代码即可验证。
5. **验证留痕**：输出一次 JS 语法检查的执行结果（命令 + 返回值）作为完成证据。

## 5. 风险清单
| # | 风险 | 影响 | 处置 |
|---|---|---|---|
| 1 | `validation_commands` 槽位缺失，环境是否有 Node 未确认 | 验证步骤可能不可执行 | 采用「`node --check` 优先，不可用则降级为语法自查 + 控制台零报错」双路径，不阻塞交付 |
| 2 | `file://` 下的加载限制（module 脚本、绝对路径 `/style.css`） | 双击打开白屏/样式丢失，直接击穿 AC2 | 强制相对路径 `./style.css`、`./script.js`，普通 `<script>` + `defer`，禁止 module 与网络请求 |

### 新增 `hello-dev/script.js`

```javascript
// 文案常量单点定义，逐字对齐需求，不做任何拼接或美化
const TEXT_INITIAL = 'Hello DEV';
const TEXT_SUCCESS = 'DEV 工作流运行成功';

function init() {
  const greeting = document.getElementById('greeting');
  const btn = document.getElementById('action-btn');

  // DOM 未就绪或元素缺失时静默返回，不抛错（保证控制台无报错）
  if (!greeting || !btn) {
    return;
  }

  // 与常量保持单一事实来源：初始态若被外部改写，这里对齐一次
  if (greeting.textContent !== TEXT_SUCCESS) {
    greeting.textContent = TEXT_INITIAL;
  }

  const handler = () => {
    greeting.textContent = TEXT_SUCCESS;   // 单次状态替换，非累加/非回退
    btn.disabled = true;                   // 终态不可逆，重复点击无副作用
    btn.removeEventListener('click', handler);
  };

  btn.addEventListener('click', handler);
}

init();
```

## 实现说明

**1. 「首屏可见 Hello DEV」不依赖 JS**
文案直接写在 `<h1 id="greeting">Hello DEV</h1>` 里，而非空标签由脚本注入。这样即使脚本加载失败，验收 3 依然成立——把最容易挂的一项从 JS 执行链上摘下来。`script.js` 里的 `TEXT_INITIAL` 对齐只是兜底幂等，不是首次渲染来源。

**2. 脚本时机（需求风险 3 的直接对策）**
`<script src="script.js" defer>` 放 `<head>`：defer 保证 DOM 解析完成后、按序执行，绑定必然成功。再叠一层 `if (!greeting || !btn) return` 守卫，守卫命中时**静默返回不抛错**，避免"验收 4 要求控制台无报错"被一句 `Cannot read properties of null` 打破。

**3. 文案字面单点化**
`Hello DEV` / `DEV 工作流运行成功` 在 `script.js` 顶部各定义一次，`DEV` 大写、中文串内部**无任何空格**、不加句号感叹号。`index.html` 中的 `<h1>` 与 `<title>` 是另外两处字面出现，Build 后会逐字回读比对——这是肉眼最容易漏的验收项，不留拼接/模板加工的空间（一律 `textContent` 直接赋值）。

**4. 单次状态替换语义**
`handler` 内替换 → `btn.disabled = true` → `removeEventListener` 自摘。禁用态视觉由 CSS `:disabled` 表达，不用 JS 切 class，避免样式与行为耦合。这严格对齐需求"非累加/非切换回退"。

**5. 零侵入保证**
只用 `write_file` 新建 `hello-dev/` 下 4 个文件，路径统一带 `hello-dev/` 前缀（相对项目根，规避 Windows cwd 漂移风险 1）；不执行任何覆盖式 shell 命令；**不产出第 5 个文件**（无 favicon、无 `.gitignore`、无 `.nojekyll`），对齐"无多余产物"的严格口径。CSS 全用 id 选择器 + 无全局 reset、无 `!important`，即使被误引入他页也不构成污染（RAG 已确认仓库内无既有 HTML 文件）。

**6. 关键取舍**
不用 ES module `import`、不用 `fetch`——`file://` 下 ES module 会被 CORS 拦截，双击直开就废了。普通 `<script src>` 零协议限制，这是"可直接本地打开"这条硬约束下的唯一稳妥选择。

**7. 已核实的前置事实**
`search_code` 确认仓库内不存在 `Hello DEV` / `DEV 工作流运行成功` 文本、不存在 `hello-dev` 引用 → 无命名冲突。RAG 注入的 5 个分块（`tests/test_core_contracts.py`、`backend/tools/search_tools.py`、`backend/trace.py`）均为后端契约/工具代码，**与本需求无关，一律不触碰**。

# Just_codding 开发提示词

## 【角色指令】
你是Just_codding的全栈开发者AI，负责按照本提示词实现一个Python AI代码开发Agent系统。
你只负责代码开发和文件创建，不进行需求分析。
不要调用cat07-req技能或任何需求分析相关技能。

## 【上下文】
参见需求概括文档 `tasks/T20260514_需求概括.md`，完整理解项目定义、工作流细节、技术栈和架构设计。

关键约束速览：
- 技术栈：Python + FastAPI + Vue 3 + LangGraph + DeepSeek API + SQLite
- 独立简历项目，非utaai-urw子模块
- 单次工作流token预算≤5元硬上限
- Shell命令仅白名单内可执行
- 角色上下文隔离：每个LangGraph节点独立对话，节点间仅传递正式产出文档
- DEV工作流审查≥1轮，DEBUG工作流审查≥2轮
- 人工验收节点不可跳过

## 【输入规范】
项目根目录：`D:\workspace\just_codding\`
已在 `tmp/` 目录下准备好以下参考文件（请先阅读）：

- `tmp/just_codding_developer_prompt.md` — 开发者角色prompt

- `tmp/T20260514_示例代码.md` — 关键模块示例代码（LangGraph工作流、预算管理、RAG检索、FC工具定义、API封装、DB表结构、FastAPI入口）

## 【输出规范】
按以下顺序创建项目文件：

### 第1步：项目骨架
- `requirements.txt`
- `backend/main.py`（FastAPI入口，路由注册，WebSocket端点）
- `backend/config.py`（配置：DeepSeek API key、白名单命令列表、预算上限5元、模型名称）
- `frontend/package.json`、`frontend/vite.config.js`、`frontend/index.html`
- `AGENTS.md`（直接复制参考文档内容到项目根目录）

### 第2步：数据库层
- `backend/db/models.py`（SQLite表：sessions、messages、artifacts、long_term_memory、rag_embeddings，使用aiosqlite异步操作）

### 第3步：工具层
- `backend/tools/file_tools.py`（read_file / write_file，含路径校验：仅允许项目源码目录内写入）
- `backend/tools/shell_tools.py`（execute_shell，白名单校验，async subprocess）
- `backend/tools/search_tools.py`（search_code，支持正则搜索项目文件）
- `backend/budget.py`（TokenBudget类：每次调用前检查+调用后累加，超限抛异常）

### 第4步：RAG系统
- `backend/rag/embedding.py`（封装sentence-transformers all-MiniLM-L6-v2）
- `backend/rag/indexer.py`（代码索引：AST解析Python文件，按函数/类分块≤500token，向量化后写入rag_embeddings表；增量更新）
- `backend/rag/retriever.py`（混合检索：关键词搜索+余弦相似度向量搜索+RRF融合排序）

### 第5步：角色Prompt（直接复制tmp/下的文件到agents/目录）
- `agents/analyst_prompt.md`、`agents/debugger_prompt.md`
- `agents/developer_prompt.md`、`agents/reviewer_prompt.md`

### 第6步：LangGraph工作流
- `backend/graph/dev_workflow.py`：DEV状态图
  - 节点：INPUT_GATE → ANALYZE → DEVELOP_PLAN → DEVELOP_BUILD → REVIEW → (条件分支：审查通过? → HUMAN_ACCEPT / FIX)
  - 每个节点调用DeepSeek API，使用role_prompt作为system_prompt
  - DEVELOP_PLAN节点完成后agent自主调用save_checkpoint切Build模式
  - 节点间通过State传递产出文档，不传对话历史
  - 审查不通过时FIX→REVIEW循环，最多3次

- `backend/graph/debug_workflow.py`：DEBUG状态图
  - 节点：INPUT_GATE → DIAGNOSE → (条件分支：论据够? → FIX / ADD_LOGGING→HUMAN_WAIT→DIAGNOSE)
  - FIX→REVIEW(第1轮)→REVIEW(第2轮)→(条件分支：通过? → HUMAN_ACCEPT / FIX循环)
  - HUMAN_WAIT节点暂停，等待用户通过API resume

### 第7步：前端
- `frontend/App.vue`（根组件，路由到Workbench）
- `frontend/components/Workbench.vue`（工作台首页：DEV/DEBUG两个入口按钮+输入框+提交）
- `frontend/components/ProgressPanel.vue`（进度面板：WebSocket实时更新当前步骤/token消耗/下一步/状态色）

## 【质量规则】
1. Plan模式严禁写文件或执行修改性命令，只读分析
2. Shell命令必须白名单校验，不在白名单内拒绝执行
3. 写文件路径校验必须在项目源码目录内
4. token消耗实时计数，超限中断并输出已完成总结
5. AI调用超时30秒，失败重试最多3次
6. 所有Python函数必须有类型注解
7. 所有IO操作用async/await
8. 遵循 `AGENTS.md` 中所有红线规则

## 【验收标准】
1. `pip install -r requirements.txt` 通过
2. `python backend/main.py` 启动FastAPI服务，`/health` 返回200
3. DEV工作流能跑通：输入任务描述 → 澄清 → 分析 → 开发 → 审查 → 完成
4. DEBUG工作流能跑通：输入BUG描述 → 诊断 → 修复 → 审查2轮 → 完成
5. token预算超限时正确中断
6. 白名单外shell命令被正确拒绝
7. Vue前端能显示进度面板（WebSocket连接正常）
